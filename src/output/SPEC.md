## Responsibility

该边界负责当前 stdio MCP 的输出预算、超限成功结果的持久化，以及模型对同一快照的按需回读。目标是避免单次工具结果无限占用上下文，同时保留可核对的完整版本；不建立长期归档或日志系统。

## Boundary

上游请求与解析由 DeepSeek 适配层负责。输出层只接收其已校验、已精简的数据；“完整”不包含搜索 compact 规则已丢弃的字段。MCP 注册层声明与可见结果对应的 schema，并把同一份受限对象同时用于 content 和 structuredContent。预算与存储不得请求上游或依赖宿主的文件读取权限。

## Output contract

- 未超限成功结果保持原有顶层结构，不归档。超限时先保存完整快照，再返回预览与 `_result`，绝不剪断整个 JSON 字符串。
- 默认每种 MCP 表示的数据 JSON 各限 12000 个 Unicode 码点，包含元数据与转义开销，不含协议外壳。不是 token 上限，也不约束多次调用累计上下文。
- search 先统一缩短摘要以保留标题/完整 URL，仍超限才移除尾部结果；元数据标明总条数与展示条数。极长来源允许被省略，不产生被剪断的 URL。
- fetch 保留连续正文开头，不拼接结尾；标题也不能绕过预算。
- 已注册工具的调用错误只返回有界、隐藏已知 API 密钥与 Bearer 凭据的摘要，不归档、不输出堆栈。落盘失败不发出 ID，也不降级到无限制全文输出。未知工具名等 JSON-RPC 协议错误保留 SDK 语义，不改成工具结果，不纳入该数据预算。

## Snapshot and pagination

完整快照是 UTF-8 编码的 JSON.stringify(data)，一经发布不再更改。服务生成 UUID v4 ID，调用方不能指定路径。read_result 使用该 JSON 文本的 Unicode 码点 offset/limit；反斜杠转义占位，片段可跨 JSON 字段与转义序列，但外层响应始终合法。

页长默认请求 4000 个码点。limit 是上界，最终响应的元数据和转义开销可能使 text 更短。next_offset 根据实际返回的码点数计算，不能由调用方用 offset+limit 推断。EOF 时 next_offset 为 null；offset 等于总长度是合法空末页，越界无效。有内容剩余的合法分页必须前进。分页响应不再归档。

读取采用有界 UTF-8 扫描，而不是每页读取全文；靠后偏移需要从文件开头扫描，未建立持久随机访问索引。读取不刷新 TTL，不重新请求 DeepSeek。可检测元数据、大小和 UTF-8 损坏，不提供防篡改保证。

## Persistence and concurrency

默认根目录是用户主目录下 .deepseek-search-mcp/results，DS_RESULT_DIR 覆盖值必须绝对。位置不依赖 npx 或工作目录，以确保重启可回读。其余配置及接口示例由 README 维护。

结果默认有效 7 天，总配额默认 512 MiB，按受管理数据和元数据的逻辑字节计量。共用根目录的进程应采用一致配额；不同配置的进程只能按各自设置执行接纳检查。先清过期，再检查新归档是否可接纳；不足则拒绝，不提前淘汰有效引用。到期检查独立于物理回收，读取不续期，服务启动、写入和每小时执行清理。确认到期后先把正式目录原子改名为待清理临时目录，再递归删除；删除中断后可无条件继续回收，不依赖已经删掉的元数据。

同根目录的本机进程通过硬链接独占锁串行化配额检查、写入与清理。锁 owner 在发布前完整写入，故障候选文件不成为锁。锁发布者还必须等待既有恢复结束并确认锁仍是自己的 inode，才能进入临界区；恢复者可能持有旧记录，发布前检查恢复标记不足以保证互斥。释放时只移除仍属于自己的锁；Windows 文件 ID 可超出 Number 的安全整数范围，候选锁、当前锁与正式文件的 dev/ino 必须用 bigint 精确比较。协调文件的消失、替换和删除过渡状态在期限内重试，不放宽正式快照文件的校验。数据和元数据在同目录暂存并完整写入后发布；未完成的目录不能被读取。根目录应使用支持硬链接和重命名的本机文件系统。

死亡写入者的锁可恢复，恢复操作本身串行协调。若恢复进程在持有恢复锁时崩溃，选择 fail-closed 而非冒险抢占：返回明确的繁忙错误，由使用者停止全部实例后清除遗留恢复锁。PID 复用同样保守处理，不以超时删除可能仍在工作的 owner。

路径只在受控根内解析，拒绝非法 ID、符号链接与非预期文件类型。新 POSIX 目录和文件使用 0700/0600，Windows 依赖目录 ACL。这是单用户 stdio 存储，不是多租户授权机制。

## Deliberate exclusions

不改变搜索字段精简、上游响应读取或现有空字段校验行为；不限制上游响应体积或进程峰值内存；不保存错误全文，不建立远程 MCP transport、全局 token 配额或宿主文件工具集成。
